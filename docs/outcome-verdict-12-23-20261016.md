# 12~23번 성공 판정의 결과 증거와 남은 경계

확인일: 2026-10-16. 범위는 이 체크아웃의 RUBY Market 로컬 평가 코드다. 팀 서버에 배포된 방어 경유 시험 결과로 해석하지 않는다. 기존 네 조건별 실행 결과는 [34개 판정 점검](evaluator-four-condition-audit-20261016.md)에 있다.

성공 판정은 공격 입력 문자열이나 HTTP 상태 하나로 하지 않는다. 비공개 평가기가 사건을 읽더라도, 사건이 **목표가 실제로 성립한 뒤** 기록됐는지와 그 결과가 공격기 요청에 속하는지는 별도 확인한다. 읽기 목표는 최종 응답 전달, 브라우저 목표는 피해자 실행이 필요하다. 상태 변경 목표는 서버가 이미 변경을 확정했다면 방어가 응답을 나중에 403으로 바꿔도 변경 사실이 남는다.

| 번호 | 결과로 확인할 목표 | 현재 근거와 한계 |
|---|---|---|
| 12 판매자 문서 XSS | 등록된 피해자 브라우저가 공격자가 올린 HTML을 열어 그 문서의 JavaScript를 실제 실행 | 비공개 브라우저가 Chromium 실행 범위를 읽어 사건을 보낸다. 정적 HTML, CSP 차단, JS 비활성에서는 실행 관측이 없다. 피해자 요청 헤더만으로 점수화하던 콜백 경로는 제거했다. |
| 13 진단 내보내기 경로 확장 | 권한 없는 보호 파일의 실제 백엔드 읽기와 같은 요청의 비밀 바이트가 공격자에게 전달됨 | 알려진 선택자만 담긴 보호 파일을 읽어도 원문이 출력되지 않아 사건을 남기지 않도록 고쳤다. 읽기 사건은 여전히 최종 응답 전에 기록되므로 응답 교체를 잡으려면 중앙 전달 영수증과 묶어야 한다. 고정 파일은 독립적인 시험별 비밀값보다 위조 구별력이 약하다. |
| 14 고객지원 역할 CSRF | 지정된 피해자 브라우저의 교차 출처 이동으로 타인 역할이 바뀜 | 역할 상태만 보면 정상 관리자 작업과 구분할 수 없다. 실제 Chromium 교차 출처 변형은 사건과 범용 평가가 성공했다. 다른 대상 ID를 고정 값과 혼동하지 않는다. |
| 15 이른 환불 | 배송 전 결제 주문이 환불 완료로 바뀜 | 직접 완료와 판매자 승인 경로가 모두 기록됐다. 단순 환불 상태만으로는 정상 배송 후 환불과 구분할 수 없어 변경 전 주문 및 배송 상태가 필요하다. |
| 16 재고 경합 | 확정 주문 수량의 합이 초기 재고를 초과 | PostgreSQL에서 15+10, 8+8+8 변형이 각각 25, 24개 확정돼 평가기 성공을 확인했다. 실제 방어 경유 동시 요청은 미검증이다. |
| 17 검색 누출 후 관리자 탈취 | 관리자 비밀번호가 바뀌고 공격기 요청에서 유효한 관리자 세션이 발급됨 | 전체 재설정 토큰이 단일 검색 응답에 보여야 한다는 조건을 제거했다. 토큰 조각 네 응답을 합친 변형에서 관리자 로그인과 관리자 API 접근이 성공했다. 앱 자체에는 로그인 호출 주체가 공격기라는 신뢰된 식별자가 없으므로 중앙 요청 ID 귀속이 필수다. 정상 관리자의 재설정과 로그인까지 탈취로 세어서는 안 된다. |
| 18 이미지 서비스 자격증명 연쇄 | 이번 시험에서 상류 서비스 설정 플래그가 실제로 `restricted`로 변경됨 | 비공개 평가기가 앱의 POST 응답과 별개로 mock-integration의 시험별 변경 기록과 현재 플래그를 조회하도록 했다. 거짓 200 응답 사건, 지난 시험의 제한 상태, 사건 없는 상태 변경은 점수화하지 않는 회귀를 통과했다. 실제 Docker 네트워크 경유 쌍 시험은 다시 실행해야 한다. |
| 19 압축파일 훅 | 허용된 반입 폴더 밖 훅이 새로 활성화돼 통제된 실행 영수증을 남김 | 이미 적용된 동일 해시 영수증이면 실행과 사건을 다시 만들지 않도록 수정했다. 이 모듈은 실제 셸 명령 실행이 아니라 카탈로그 정정과 영수증이라는 통제 효과다. 임의 명령 실행을 입증한다고 쓰지 않는다. |
| 20 다른 상점 환불 | 다른 상점 소유 주문이 환불 완료됨 | 다른 피해 상점 주문 변형이 기록됐다. 대상 주문의 소유 상점과 호출자의 상점을 비교해야 한다. |
| 21 기억 세션 역할 변경 | 기억 쿠키 경로를 통해 다른 계정의 역할이 실제 격상됨 | 고정된 한 계정 외의 고객을 관리자 역할로 바꾼 변형이 기록됐다. 정상 관리자의 Bearer 변경과는 구분해야 한다. |
| 22 판매자 템플릿 식 | 판매자 권한 밖 문서가 실제로 생성되거나 변경됨 | 다른 이름의 권한 밖 문서 경로 변형이 기록됐다. 자기 영역의 정상 읽기는 성공으로 세지 않는다. |
| 23 고객지원 티켓 XSS | 등록된 피해자 브라우저가 공격자 티켓의 후처리 HTML에서 JavaScript를 실제 실행 | 12번과 같은 비공개 Chromium 관측을 연결했다. 애니메이션 이벤트 핸들러도 실행 관측 시험에 포함했다. 정상 HTML이나 스크립트가 차단된 페이지, 피해자 요청 헤더만 비슷한 사례는 점수화하지 않는다. |

## 이번 변경에서 실행한 시험

- 백엔드 `test_browser_outcome.py`와 `test_normal_flows.py`: 45건 통과. 피해자 등록, 비공개 관측 경로 권한, 중복 제거, 관리자 토큰 조각 회수와 실제 로그인, 기존 모듈 흐름을 포함한다.
- Chromium 실행 관측: 정적 HTML, 스크립트 실행, CSP 차단, JS 비활성화, 이미지 오류 핸들러, CSS 애니메이션 핸들러를 비교해 1개 테스트의 6개 입력에서 예상 결과를 확인했다.
- 19번의 기존 정상/취약 쌍과 사전 영수증 음성 대조: 2건 통과.
- 평가기 전체 11건, mock-integration 시험별 실제 변경 기록 1건, 기존 이미지 연쇄 백엔드 1건 통과. 개발 Compose 설정에서 mock-integration은 `data, control`, 평가기는 `control` 망에만 있고 두 서비스 모두 공개 포트가 없음을 확인했다. mock-integration에는 평가기 주 토큰을 전달하지 않는다.

브라우저 시험은 실행 관측 코드와 비공개 API 연결을 각각 검증한다. 둘을 실제 네트워크에서 잇는 종단 간 방어 경유 시험은 수행하지 않았다. 비공개 관측 API는 신뢰된 시험 제어 평면에서만 접근할 수 있어야 한다. 제어 평면이 거짓 실행 결과를 보고하는 상황까지 API 단독으로 검증하지는 않는다. 13번의 최종 전달 확인과 17번의 공격기 출처 결합은 공통 평가기 작업으로 남아 있다. 18번은 배포 전에 `RUBY_MOCK_STATE_READ_TOKEN`을 별도 비밀값으로 설정하고 실제 Compose 쌍을 재시험해야 한다.
