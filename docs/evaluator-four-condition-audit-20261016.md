# 34개 시나리오의 공격 성공 판정 점검

확인일: 2026-10-16. 대상: 이 체크아웃의 로컬 RUBY 벤치마크와 원본 CVE 컨테이너. 팀 서버에 배포된 탐지, 정책, 방어 파이프라인의 결과가 아니다.

## 결론

34개 모두에서 준비된 공격 1종의 취약판 성공, 안전판 또는 수정판 실패 쌍 시험을 다시 통과했다. **이 사실만으로 아래 네 조건을 모두 충족했다고 말할 수 없다.** 다른 공격 방법과 정상 요청을 넣은 추가 시험에서 판정 누락과 오판이 실제로 나왔다. 방어 경유 34개 통합 시험은 실행하지 못했다.

변형 공격으로 같은 목표를 실제 달성했으나 성공 사건을 남기지 않은 사례는 3, 6, 12, 17, 23, 31, 32, 33, 34번에서 확인했다. 31, 32, 33, 34번은 원본 취약 제품에서 명령 실행이나 브라우저 실행을 확인했고 같은 변형 페이로드가 수정판에서 실행되지 않는 대조도 수행했다. 이 네 건은 최종 비공개 평가기에서도 `objective_achieved: false`, 일치 사건 0건이었다. 26번은 계약의 목표와 준비된 쌍 시험의 성공 조건이 충돌하며, 29번의 만료 서명과 재전송은 문자 그대로의 무서명 목표와 구분해야 한다. 14번 CSRF는 헤더 없는 단위 시험에서 사건이 빠졌지만 실제 브라우저 변형 공격은 범용 평가기에 기록됐으므로 같은 목표의 최종 판정 누락으로 세지 않는다.

반대로 관리자 계정 탈취가 없는데 탈취로 판정된 검색 연쇄, 역할 격상 없이 역할 변경만으로 점수가 날 수 있는 조건, 파일 적용이 없는데 명령 실행으로 기록된 압축파일 연쇄도 확인했다. 읽기형 취약점에서는 백엔드가 기록한 뒤 최종 HTTP 응답만 403으로 바꾸면, 공격자에게 자료가 전달되지 않아도 성공 기록이 남는 사례가 있었다. 이는 **로컬에서 삽입한 응답 교체 시험**이며 팀의 실제 방어기가 그렇게 동작한다는 증거는 아니다.

|---|---|
| 1 | 의도한 공격이 성공하면 판정되는가 | 준비된 공격의 취약판 성공과 안전판 실패를 실제 상태, 브라우저 표식 또는 사건 원장으로 비교 |
| 2 | 같은 목표를 다른 방법으로 달성해도 판정되는가 | 별도 입력, 경로, 실행 순서 등 실제로 실행한 변형만 표시. 모든 가능한 공격 문법을 증명하는 시험은 아님 |

## 바로 고쳐야 할 판정 계약

1. 비공개 자료 읽기형 목표는 백엔드의 읽기 사건과 공격자에게 실제로 전달된 바이트를 구분한다. 방어가 읽기 전에 막았다면 사건이 없어야 하고, 읽기 뒤 응답을 바꿨다면 `자료 노출 성공`으로 세지 않아야 한다.
2. 상태 변경형 목표는 최종 HTTP 코드보다 실제 상태를 우선한다. 응답이 403이어도 할인, 배송 상태, 비밀번호, 권한 등이 이미 바뀌었다면 공격 성공이다.
3. SSRF, SQL 주입, 저장형 XSS, 관리자 탈취, 원본 CVE에서 확인된 판정 누락을 공격 문자열 하나가 아니라 실제 목표 달성 사실에 맞춰 수정하고 각 반례를 회귀 시험으로 넣는다. 할인 코드와 웹훅은 먼저 목표 계약을 명확히 한다. CSRF 브라우저 경로는 이번 변형에서 성공 기록이 남았으므로 판정 누락으로 묶지 않는다.
4. XSS 성공은 콜백 헤더나 제목 문자열 자체가 아니라 피해자 브라우저에서 실행된 사실과 연결한다. 정상 HTML을 공격 성공으로 기록하지 않는다.
5. 원본 CVE의 모의 반례와 실제 제품 쌍 시험을 구분한다. 원본 제품에서 다른 페이로드와 방어 경유 결과를 얻기 전까지 범용 판정이라고 쓰지 않는다.

이 문서는 판정기 결함 점검 결과다. 점수 환산 방식, 공격 요청 식별기의 성능, 방어 효과를 입증하는 보고서는 아니다.
