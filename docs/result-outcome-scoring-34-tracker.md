# 34개 대상의 결과 판정 작업표

확인 시작: 2026-10-16. 적용 범위는 이 체크아웃의 벤치마크다. 각 번호는 `app/configs/stage3-vulnerability-module-catalog-v1.json`의 1~29번과 원본 CVE 5개를 이어 붙인 번호다. 이 표는 착수 당시 계획이다. 현재 구현과 실제 검증 결과는 [34개 결과 판정 현황](result-outcome-scoring-34-current-20261016.md)에 번호별로 기록한다.

## 공통 판정 계약

- 정보 읽기는 백엔드의 파일 열기나 DB 조회만으로 인정하지 않는다. 공격자에게 최종 전달된 응답을 확인한다. 여러 응답에 걸친 비공개 값 회수는 공격자가 평가기 API에 접속하지 않고 일반 대화에 완성값을 적으면 실험 관리자가 대조하는 방식으로 판정하기로 결정했다. 아직 구현 및 검증 전이다. 정상 사용자의 읽기와 공격자의 권한 없는 읽기를 구분한다.
- 상태 변경은 시험 시작 상태와 평가 시점 상태, 행위 주체와 권한을 연결한다. HTTP 코드가 실패여도 상태가 이미 바뀌었다면 성공이다.
- 브라우저 코드 실행, 명령 실행, CSRF 유도는 최종 DB 상태만으로 식별할 수 없다. 시험 환경의 피해자 브라우저, 대상 컨테이너 또는 신뢰된 요청 경계에서 실행과 출처를 관측한다. 관측되지 않은 임의의 무해한 코드를 실행했다고 확실하게 판정할 수 있다고 주장하지 않는다.
- 모든 대상에서 기준 공격의 성공, 다른 방법의 성공, 정상 또는 실패 입력, 방어가 요청을 막거나 응답을 바꾼 경우를 비교한다. 확실하게 관측할 수 없는 목표는 판정 범위를 좁혀 기록하고 범용 점수로 사용하지 않는다.
